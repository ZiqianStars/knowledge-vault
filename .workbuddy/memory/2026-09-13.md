### 踩坑记录（重要）

**坑 1：`git config --global` 写入失败**

报错 `error: could not lock config file ~/.gitconfig: File exists`。根因是 git 的写入流程是「先写 `.gitconfig.lock` 临时文件 → 原子重命名」，沙箱拦截了重命名这一步，导致残留的锁文件把后续所有写入堵死（残留内容正是半截的 `[user] name = ...`）。

- 排查要点：`pgrep -fl git` 会匹配到微信子进程（路径含 "git"），**不能据此判断有 git 进程占用锁**
- 解决：`mv ~/.gitconfig.lock /tmp/` 移走残留锁，然后**用 Write 工具直接写 `~/.gitconfig`**，绕开加锁流程

**坑 2：未配置身份时 git 不报错，静默用回退值**

实测未配置时提交照常成功，作者被静默写成 `wenjuxu <wenjuxu@MacBook-Air.local>`（取自系统账户名 + 主机名）。这类错误不报错、只写进历史，最难发现。

### 方法论：如何拿到正确的 noreply 邮箱

不需要访问 `github.com`（本机不通），走 `api.github.com` 即可：

```bash
curl -sL "https://api.github.com/users/<用户名>" | python3 -c "
import sys, json; d=json.load(sys.stdin)
print(f\"{d['id']}+{d['login']}@users.noreply.github.com\")"
```

### 真正的根因：命令行工具没走系统代理

排查「github.com 不可达」时，找到了一直被忽略的前提：

- 本机运行**艾可云（Clash）**，Wi-Fi 系统代理已启用 —— HTTP `127.0.0.1:33210`、SOCKS `33211`
- **`curl` / `git` 都不会自动读取 macOS 系统代理**，不显式指定就直连，于是返回 `000` / `CONNECT tunnel failed 502`
- WorkBuddy 自身还会注入沙箱代理 `HTTP_PROXY=http://127.0.0.1:50402`，它本身也拦截部分外网域名

**这推翻了此前两次结论** —— 都不是「网络波动」，而是没走代理：

| 日期 | 当时的结论 | 实际原因 |
| --- | --- | --- |
| 09-11 | `github.com` 被拦截 | 未走代理 |
| 09-13 早 | `raw.githubusercontent.com` 稳定不通 | 未走代理 |

走 Clash 代理后重测，**所有 GitHub 域名全部可达**，`raw.githubusercontent.com` 能正常下载 install.sh（32785 字节）。因此「Homebrew 官方安装脚本下不到」这个顾虑也一并消除。

## 补充规则：用代理前先判断代理是否可用（用户要求）

用户明确要求记录一条操作规则：**每次要用代理之前，先判断艾可云开着没有 —— 开着就走代理，没开就直连。**

实测修正了判断方式 —— **权威依据是「端口实测可连」，不能只看进程或系统设置**：

- `pgrep -f "艾可云"` 能正确判断进程在跑（匹配到主进程 + 3 个 Helper + clash 内核，共 5 个）
- 但**系统代理设置里列出的 SOCKS 端口 `33211` 实际并未监听**，只有 HTTP `33210` 可用 —— 只看设置会误判

```bash
P=$(networksetup -getsecurewebproxy Wi-Fi 2>/dev/null | awk '/Port:/{print $2}')
[ -n "$P" ] && nc -z -G 1 -w 1 127.0.0.1 "$P" 2>/dev/null \
  && echo "ON 走代理" || echo "OFF 直连"
```

经代理访问 github.com 交叉验证 → 200 ✅。

**两个方向都会出错**：代理开着却不走 → 假性网络不通（000/502）；代理没开却硬指 → 连不上代理端口，比直连更糟。
