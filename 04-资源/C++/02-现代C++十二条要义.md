# 现代 C++ 十二条要义

> 原文：[欢迎回到 C++ - 现代 C++ | Microsoft Learn](https://learn.microsoft.com/zh-cn/cpp/cpp/welcome-back-to-cpp-modern-cpp?view=msvc-170)

## 一句话概括

> MSVC 官方文档给的一张「告别 C 风格写法」清单：**用 RAII 管资源、用容器管内存、用 `auto`/lambda/`constexpr` 管冗余代码**——相同的性能，少一半的 bug。

## 核心内容

> 官方原文的前提：以下特性**默认要求 C++11 及以上**，MSVC 侧由编译选项 [`/std`](https://learn.microsoft.com/zh-cn/cpp/build/reference/std-specify-language-standard-version?view=msvc-170) 控制标准版本。

### 1. RAII + 智能指针 —— 干掉 `new`/`delete`

C 风格编程最常见的 bug 是**内存泄漏**：`new` 出来的忘了 `delete`。现代 C++ 的解法是 RAII（资源获取即初始化）：

> 资源（堆内存、文件句柄、套接字）应**归对象所有**——构造函数里获取，析构函数里释放。对象离开作用域时，资源必然归还。

标准库提供三种智能指针：

| 指针 | 语义 | 什么时候用 |
| --- | --- | --- |
| [`std::unique_ptr`](https://learn.microsoft.com/zh-cn/cpp/standard-library/unique-ptr-class?view=msvc-170) | 独占所有权 | **默认选项** |
| [`std::shared_ptr`](https://learn.microsoft.com/zh-cn/cpp/standard-library/shared-ptr-class?view=msvc-170) | 引用计数共享 | 确有多方共同持有时 |
| [`std::weak_ptr`](https://learn.microsoft.com/zh-cn/cpp/standard-library/weak-ptr-class?view=msvc-170) | 不增加计数的观察者 | 打破 `shared_ptr` 循环引用 |

```cpp
#include <memory>
class widget {
private:
    std::unique_ptr<int[]> data;
public:
    widget(const int size) { data = std::make_unique<int[]>(size); }
    void do_something() {}
};

void functionUsingWidget() {
    widget w(1000000);   // 生命周期自动绑到当前作用域
    w.do_something();
}   // w 和 w.data 在此自动析构并释放
```

**规则**：尽可能用智能指针；**如果必须手写 `new`/`delete`，必须包进 RAII 对象**。

### 2. `std::string` / `std::string_view` —— 干掉裸字符串

C 风格字符串是第二大 bug 来源。用 `std::string` / `std::wstring` 替换，几乎消除全部相关错误，还白得 `find`、`append`、`prepend` 等成员函数，且高度优化过。

**只读场景**：C++17 起用 [`std::string_view`](https://learn.microsoft.com/zh-cn/cpp/standard-library/basic-string-view-class?view=msvc-170)，避免拷贝开销。

### 3. 容器 —— 干掉 C 风格数组

容器全部遵循 RAII、提供迭代器、经过充分测试与性能优化。**默认序列容器是 `vector`，默认关联容器是 `map`（不是 `unordered_map`）**。

```cpp
vector<string> apples;
apples.push_back("Granny Smith");

map<string, string> apple_color;
apple_color["Granny Smith"] = "Green";
```

**官方给的选型指引**：

- 常规：`vector` / `map`；去重与多值：`set` / `multimap` / `multiset`
- 需要性能优化时考虑：`unordered_map`（单元素开销更低、查找 O(1)，但更难用对）；或者**排序后的 `vector`**
- 需要对接老 API 的裸指针访问器：`f(vec.data(), vec.size());`
- **不要用 C 风格数组**

### 4. 标准库算法 —— 先查再写

写自定义算法之前，先查 [`<algorithm>`](https://learn.microsoft.com/zh-cn/cpp/standard-library/algorithm?view=msvc-170)。C++17 起许多算法有并行版本。

| 算法 | 用途 |
| --- | --- |
| `for_each` | 默认遍历（通常与 range-for 二选一） |
| `transform` | 非原位修改元素 |
| `find_if` | 默认搜索 |
| `sort` / `lower_bound` | 默认排序与有序查找 |

**写比较器用严格 `<`**，并优先用**命名 lambda**：

```cpp
auto comp = [](const widget& w1, const widget& w2)
    { return w1.weight() < w2.weight(); }

sort( v.begin(), v.end(), comp );
auto i = lower_bound( v.begin(), v.end(), widget{0}, comp );
```

### 5. `auto` —— 干掉冗余类型名

```cpp
map<int,list<string>>::iterator i = m.begin();  // C-style
auto i = m.begin();                             // modern C++
```

在推导类型是嵌套模板时尤其有用。

### 6. 基于范围的 `for` —— 干掉索引错误

```cpp
std::vector<int> v {1,2,3};

for(int i = 0; i < v.size(); ++i)   // C-style：易错、啰嗦
    std::cout << v[i];

for(auto& num : v)                  // modern C++
    std::cout << num;
```

同时适用于标准库容器和原始数组。

### 7. `constexpr` —— 干掉宏

```cpp
#define SIZE 10           // C-style：易错、难调试
constexpr int size = 10;  // modern C++
```

### 8. 统一初始化（`{}`）

任何类型都可用花括号初始化；初始化容器尤其省事：

```cpp
struct S {
    std::string name;
    float num;
    S(std::string s, float f) : name(s), num(f) {}
};

std::vector<S> v2 {s1, s2, s3};
std::vector<S> v3{ {"Norah", 2.7}, {"Frank", 3.5}, {"Jeri", 85.9} };  // 逐元素推断类型
```

### 9. 移动语义 —— 干掉不必要的拷贝

移动操作**把资源所有权从一个对象转移给另一个**，而不是复制一份。拥有堆内存、文件句柄等的类可以定义**移动构造函数**和**移动赋值运算符**；重载决议时若无需拷贝，编译器会优先选它们。**定义了移动构造函数的类，标准库容器类型会在对象上调用它。**

### 10. Lambda 表达式 —— 干掉函数指针

函数指针不便于维护、不在调用点附近定义、也不类型安全。现代 C++ 用**函数对象**（重载了 `operator()` 的类），最便捷的内联写法就是 lambda：

```cpp
std::vector<int> v {1,2,3,4,5};
int x = 2, y = 4;
auto result = find_if(begin(v), end(v), [=](int i) { return i > x && i < y; });
```

`[=]` 表示按值**捕获**外围的 `x`、`y`——lambda 持有它们各自的副本。

### 11. 异常 —— 优于错误码

> 现代 C++ 更看重**异常**，把它作为报告和处理错误条件的**首选方式**，而非错误码。

详见 [现代 C++ 处理异常和错误的最佳做法](https://learn.microsoft.com/zh-cn/cpp/cpp/errors-and-exception-handling-modern-cpp?view=msvc-170)。

### 12. `std::atomic` 与 `std::variant`

- **线程间通信**用 [`std::atomic`](https://learn.microsoft.com/zh-cn/cpp/standard-library/atomic-structure?view=msvc-170) 及相关类型
- **`union` 的类型安全替代品**是 C++17 的 [`std::variant`](https://learn.microsoft.com/zh-cn/cpp/standard-library/variant-class?view=msvc-170)，用 [`std::visit`](https://learn.microsoft.com/zh-cn/cpp/standard-library/variant-functions?view=msvc-170#visit) 类型安全地访问成员

## 我的理解

- **这 12 条不是「风格偏好」，它们的共同目标是同一个：把「资源生命周期」和「手写的正确性问题」从程序员手里转移到编译器和标准库手里。** `unique_ptr` 替你决定何时 `delete`，range-for 替你决定边界，`variant` 替你保证类型安全。辨认一段代码算不算现代 C++，就看它有没有把这类责任交出去。
- **官方的容器选型建议值得单独记住**：默认 `map` 而不是 `unordered_map`，性能要调优才考虑后者或「排序后的 `vector`」。这和社区里「默认用哈希表」的直觉相反——原因是 `unordered_map` 单元素开销更高、且哈希函数选不好容易退化。**不要凭「平均 O(1)」就默认它更快，实测。**
- **文档反复出现的字样是「modern C++ 代码更简单、安全、美观，而且速度仍像以往一样快」**——这句话的潜台词是：这些写法是**零开销抽象**，不是「用安全性换性能」的交易。理解这一点，才敢在性能敏感的项目里照样用 `vector` 和 `unique_ptr`。
- **原文有一处容易被误读**：第 4 条里 `find_if` 用了 `[=]`（按值捕获）。对标量没问题，但对容器或大对象，`[=]` 会静默产生拷贝。**实践上优先显式写出捕获列表**（`[&x]` 或 `[x]`），这比 `[=]`/`[&]` 安全，也不牺牲可读性。
- **这 12 条全部是 C++11/17 特性，到今天已经 15 年了。** 也就是说，「现代 C++」这个词本身已经不现代——真正新的东西（`concept`、`coroutine`、modules、ranges）在这份清单里一条都没有。这是 MS 文档的老读者口味，做技术选型时不要用这篇来判断 C++ 的前沿状态。

## 可行动的结论

- [ ] 给自己一条硬规则：**新代码里出现 `new`/`delete` 或 C 风格数组，必须在 code review 里被问一句为什么**
- [ ] 现有的宏常量改成 `constexpr`；`#define SIZE 10` 这类逐个替换
- [ ] 检查现有代码中手写的 for 索引循环，能换 range-for 的换掉
- [ ] lambda 捕获列表：把 `[=]` / `[&]` 换成显式捕获，避免容器被静默拷贝
- [ ] 确认项目的 `/std` 选项（MSVC 默认不是最新标准），决定是 `/std:c++20` 还是照旧
