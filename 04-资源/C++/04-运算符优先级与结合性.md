# 运算符优先级与结合性

> 原文：[C++ 内置运算符、优先级和关联性 | Microsoft Learn](https://learn.microsoft.com/zh-cn/cpp/cpp/cpp-built-in-operators-precedence-and-associativity?view=msvc-170)

## 一句话概括

> 一张从高到低的 **16 级优先级表**。**优先级决定谁先算，结合性决定同级里谁和谁绑**——只有第 3 级（一元运算符）和第 15 级（赋值、`?:`、`throw`）是从右往左，其余全部从左往右。

## 核心内容

### 完整优先级表（第 1 级最高）

| 级别 | 运算符 | 含义 | 结合性 |
| --- | --- | --- | --- |
| **1** | `::` | 范围解析 | 无关联 |
| **2** | `.` `->` `[]` `()` `++`(后缀) `--`(后缀) `typeid` `const_cast` `dynamic_cast` `reinterpret_cast` `static_cast` | 成员访问、下标、函数调用、后缀自增自减、类型转换关键字 | **左 → 右** |
| **3** | `sizeof` `++`(前缀) `--`(前缀) `~` **compl** `!` **not** `-`(一元) `+`(一元) `&`(取地址) `*`(解引用) `new` `delete` `()`(强制转换) | 全部一元运算符 | **右 → 左** ⚠️ |
| **4** | `.*` `->*` | 指向成员的指针（对象/指针） | 左 → 右 |
| **5** | `*` `/` `%` | 乘法、除法、取模 | 左 → 右 |
| **6** | `+` `-` | 加法、减法 | 左 → 右 |
| **7** | `<<` `>>` | 左移、右移 | 左 → 右 |
| **8** | `<` `>` `<=` `>=` | 关系运算 | 左 → 右 |
| **9** | `==` `!=` **not_eq** | 相等性 | 左 → 右 |
| **10** | `&` **bitand** | 按位与 | 左 → 右 |
| **11** | `^` **xor** | 按位异或 | 左 → 右 |
| **12** | `\|` **bitor** | 按位或 | 左 → 右 |
| **13** | `&&` **and** | 逻辑与 | 左 → 右 |
| **14** | `\|\|` **or** | 逻辑或 | 左 → 右 |
| **15** | `? :` `=` `*=` `/=` `%=` `+=` `-=` `<<=` `>>=` `&=` **and_eq** `\|=` **or_eq** `^=` **xor_eq** `throw` | 条件、全部赋值运算符、抛出 | **右 → 左** ⚠️ |
| **16** | `,` | 逗号 | 左 → 右 |

> 原文特别注明：**同一级别编号内的运算符优先级完全等同**，除非用括号显式改变关系。

### 替代拼写（alternative spelling）

C++ 为部分运算符规定了**关键字形式的等价拼写**，主要用于非 ASCII 键盘环境：

| 运算符 | 替代拼写 | | 运算符 | 替代拼写 |
| --- | --- | --- | --- | --- |
| `~` | `compl` | | `&&` | `and` |
| `!` | `not` | | `\|\|` | `or` |
| `!=` | `not_eq` | | `&=` | `and_eq` |
| `&` | `bitand` | | `\|=` | `or_eq` |
| `^` | `xor` | | `^=` | `xor_eq` |
| `\|` | `bitor` | | | |

**三个关键事实：**

1. 在 **C** 里，这些不过是 `<iso646.h>` 中的宏；在 **C++** 里它们是**语言层面的关键字**。
2. C++ 侧的 `<iso646.h>` / `<ciso646>` **已弃用**。
3. **MSVC 下需要** [`/permissive-`](https://learn.microsoft.com/zh-cn/cpp/build/reference/permissive-standards-conformance?view=msvc-170) **或** [`/Za`](https://learn.microsoft.com/zh-cn/cpp/build/reference/za-ze-disable-language-extensions?view=msvc-170) **才能让它们生效**。默认（开启 MS 扩展）时它们不是关键字。

## 我的理解

- **这张表真正需要背的只有三条：**(1) 第 2 级的后缀运算、成员访问、函数调用绑得**极紧**，比任何一元运算符都紧；(2) 第 3 级一元和第 15 级赋值是**仅有的两个右结合**组；(3) **位移 `<< >>` 低于算术、高于关系**——`a << 1 + 2` 等价于 `a << (1 + 2)`，这是位操作里最常见的错误来源。
- **第 10–12 级把三类按位运算拆开了，很多人误以为它们同级。** `a & b | c` 实际是 `(a & b) | c`。更阴险的是**相等性在第 9 级，高于第 10 级的按位与**：写出 `x & 0xFF == 0xFF` 时，实际解析成 `x & (0xFF == 0xFF)`，也就是 `x & 1`——完全不是想要的「取低 8 位再比较」。凡是位运算和比较混写，**一律加括号**，别赌记忆。
- **优先级只决定「怎么解析」，不决定「求值顺序」。** 这是两个常被混为一谈的概念：`f() + g()` 里谁先被调用**是未指定的（C++17 前），和 `+` 的优先级毫无关系。涉及副作用的表达式，靠拆分语句而不是靠记规则。
- **MSVC 关于替代拼写需要 `/permissive-` 这条规定，会造成真实的跨平台行为差异**：同样的 `a && b` 写成 `a and b`，在 clang/gcc 下默认 OK，在 MSVC 默认配置下可能编不过。**如果代码要跨 MSVC 和 GCC/Clang，不要用替代拼写**——它带来的收益（可读性）远小于它带来的编译配置耦合。

## 值得追问的问题

- 第 15 级里 `throw` 和赋值运算符同级右结合——这意味着 `throw a = b` 会被怎么解析？实践中为什么没人这么写？
- `<<` 既是位移也是流插入运算符：重载后它的优先级是否改变？（答案：不改变——重载只改语义不改优先级，这是 iostream 里 `cout << a ? x : y` 出错的根因）
- C++17 明确了哪些表达式的求值顺序？哪些仍然是未指定行为？
