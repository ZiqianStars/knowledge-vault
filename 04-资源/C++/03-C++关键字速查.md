# C++ 关键字速查（含 MSVC 扩展）

> 原文：[关键字 (C++) | Microsoft Learn](https://learn.microsoft.com/zh-cn/cpp/cpp/keywords-cpp?view=msvc-170)

## 一句话概括

> 一张全表：**93 个标准 C++ 关键字** + **43 个 MSVC 专用双下划线关键字**——前者在写可移植代码，后者在读 MSVC 项目时必然会撞上。

## 核心内容

### 一、标准 C++ 关键字（93 个）

```
alignas      alignof      and(B)       and_eq(B)    asm(a)       auto
bitand(B)    bitor(B)     bool         break        case         catch
char         char8_t(C)   char16_t     char32_t     class        compl(B)
concept(C)   const        const_cast   consteval(C) constexpr    constinit(C)
continue     co_await(C)  co_return(C) co_yield(C)  decltype     default
delete       do           double       dynamic_cast else         enum
explicit     export(C)    extern       false        float        for
friend       goto         if           inline       int          long
mutable      namespace    new          noexcept     not(B)       not_eq(B)
nullptr      operator     or(B)        or_eq(B)     private      protected
public       register     reinterpret_cast  requires(C)  return   short
signed       sizeof       static       static_assert static_cast struct
switch       template     this         thread_local throw        true
try          typedef      typeid       typename     union        unsigned
using        virtual      void         volatile     wchar_t      while
xor(B)       xor_eq(B)
```

**三组脚注，每条都踩着坑：**

| 标记 | 含义 | 说明 |
| --- | --- | --- |
| **`a`** | `asm` | MSVC 用 `__asm` 取代了 C++ 的 `asm` 语法。`asm` 保留仅为兼容其他实现，**在 MSVC 上实际无效**；x86 内联汇编请用 `__asm`（其他目标不支持内联汇编）。 |
| **`B`** | 替代运算符拼写 `and` `and_eq` `bitand` `bitor` `compl` `not` `not_eq` `or` `or_eq` `xor` `xor_eq` | **只有在** [`/permissive-`](https://learn.microsoft.com/zh-cn/cpp/build/reference/permissive-standards-conformance?view=msvc-170) **或** [`/Za`](https://learn.microsoft.com/zh-cn/cpp/build/reference/za-ze-disable-language-extensions?view=msvc-170)（禁用语言扩展）**下才是关键字**；MS 扩展开启时它们不是关键字。 |
| **`C`** | `char8_t` `concept` `consteval` `constinit` `co_await` `co_return` `co_yield` `export` `requires` | 需要 [`/std:c++20`](https://learn.microsoft.com/zh-cn/cpp/build/reference/std-specify-language-standard-version?view=msvc-170) 或更高（含 `/std:c++latest`）。 |

### 二、MSVC 专用关键字：43 个双下划线关键字

Microsoft 的约定是**给自家关键字加双下划线前缀**。启用 MS 扩展（默认）时可用；出于向后兼容，**绝大多数也接受单下划线写法**。

| 分类 | 关键字 |
| --- | --- |
| **调用约定** | `__cdecl` `__fastcall` `__stdcall` `__thiscall` `__vectorcall` |
| **宽度确定的整型** | `__int8` `__int16` `__int32` `__int64` |
| **SIMD 类型** | `__m64` `__m128` `__m128d` `__m128i` |
| **声明/存储扩展** | `__declspec` `__based` `__restrict` `__unaligned` `__w64` `__inline` `__forceinline` `__wchar_t` |
| **类型查询** | `__alignof` `__uuidof` |
| **指针尺寸标注** | `__ptr32` `__ptr64` `__sptr` `__uptr` |
| **继承模型控制** | `__single_inheritance` `__multiple_inheritance` `__virtual_inheritance` |
| **结构化异常处理 (SEH)** | `__except` `__finally` `__leave` |
| **内联汇编** | `__asm` |
| **事件处理** | `__event` `__raise` `__hook` `__unhook` |
| **编译器假设** | `__assume` `__noop` |
| **模板/成员存在性检查** | `__if_exists` `__if_not_exists` |
| **接口与基类** | `__interface` `__super` |

**必须单独记住的三条替换关系：**

| 标准写法 | MSVC 实际 | 说明 |
| --- | --- | --- |
| `typedef unsigned short wchar_t` | `__wchar_t` | `__wchar_t` 是原生 `wchar_t` 的 MS 专用同义词。`/Zc:wchar_t-` 可把 `wchar_t` 变回 `unsigned short` 的 typedef。 |
| `int` / `short` / `long long` / `char` | `__int32` / `__int16` / `__int64` / `__int8` | 四组互为 MS 侧别名，见 [[05-内置类型与大小]] |
| `asm` | `__asm` | 见前文脚注 `a` |

> **`__cdecl` 是例外**：MSVC 提供的 `__cdecl` 版本**没有前导下划线**（即 `_cdecl` 也能用）。

### 三、`__declspec` 的上下文关键字（不含双下划线前缀）

`__declspec(...)` 里填的修饰符设计上像关键字。官方列出：

`align` · `allocate` · `allocator` · `appdomain` · `code_seg` · `deprecated` · `dllexport` · `dllimport` · `jitintrinsic` · `naked` · `noalias` · `noinline` · `noreturn` · `no_sanitize_address` · `nothrow` · `novtable` · `process` · `property` · `restrict` · `safebuffers` · `selectany` · `spectre` · `thread` · `uuid`

其中 **`dllexport` / `dllimport`** 是 Windows DLL 开发的日常必需品。

### 四、C++/CLI 与 C++/CX —— 见到就跑的那一批

| 状态 | 关键字 |
| --- | --- |
| **已弃用**（`f`，原「C++ 托管扩展」） | `__abstract` `__box` `__delegate` `__gc` `__nogc` `__pin` `__property` `__sealed` `__try_cast` `__value` |
| C++/CLI 上下文（`G`） | `abstract` `array` `delegate` `event` `gcnew` `generic` `initonly` `interface class` `literal` `ref class` `ref struct` `sealed` `value class` `for each in` `finally` |

> 官方原文明确标注：带 `f` 标记的 C++ 托管扩展语法**现已弃用**。新代码不要碰。

## 我的理解

- **最值得记住的不是清单本身，而是「替代运算符拼写那条」**。`and`/`or`/`not` 在 MSVC 默认情况下**不是关键字**——这意味着它们可以被合法地用作变量名，也意味着加了 `/permissive-` 之后，原本能编过的代码会突然编不过。**这是一个由编译选项导致的真实兼容性断点**，跨编译器移植时最容易在这里踩雷：clang/gcc 默认把它们当关键字，MSVC 默认不当。
- **双下划线前缀是一条极强的信号：看到 `__` 开头，立刻判断这段代码不可移植。** 反过来，如果一份代码里双下划线关键字扎堆（`__declspec(dllimport)`、`__stdcall`、`__int64`），基本可以确定它诞生于 Windows/Visual Studio 环境且未做移植处理——这比读 README 判断快得多。
- **`__int64` / `__cdecl` 这类「单下划线也行」的宽容背后是历史债。** MSVC 为了兼容上世纪的老编译器，留下了一批 `_cdecl`、`_stdcall` 写法。现在调用约定一般通过宏或 `[[]]` 属性处理，不必依赖这些关键字。
- **「全表 93 个」这个数字本身不是稳定的**。每次标准升级都会增加（`consteval`/`constinit`/`co_*` 都是 C++20 加进来的）。看到网上流传的「C++ 有 63 个关键字」之类的说法，几乎都是 C++98 时代的旧数据——**查权威来源，不要背数字**。

## 值得追问的问题

- `/permissive-` 会让 `and`/`or` 变成关键字——如果现有代码把它们当变量名，迁移时要改多少处？有无自动化手段？
- `__cdecl`、`_cdecl`、`__cdecl` 三者 MSVC 都接受，那么 `/Za` 下还能用吗？
- `alignas` 与 `__declspec(align)` 行为是否完全等价？在跨 GCC（`__attribute__((aligned))`）场景下如何统一？
