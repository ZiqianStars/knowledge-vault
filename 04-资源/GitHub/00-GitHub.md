## 一条主线

> 找到 → 看懂 → 判断 → 拿到手 → 贡献出去

这五步的顺序不是随便排的。**许可证必须在动手之前看**，因为它决定的是「你能不能把代码闭源进商业产品」——这是唯一一步做错了无法挽回的。其他几步返工成本都低。

## 常见误区

| 误区 | 纠正 |
| --- | --- |
| 「下载 Zip 就等于装了」 | Zip 里只有源码快照，没有 Git 历史，不能 `git pull`，装不上 |
| 「Star 数高 = 安全可靠」 | Star 只代表 popularity，不代表代码质量和维护活跃度 |
| 「MIT 和 GPL 差不多」 | 差别是能不能闭源商用，是法律层面的事 |
| 「用 Release 下载的 exe 可以直接改」 | Release 是作者打包的成品，要改就得 Clone 源码 |
| 「GitHub 只是个代码托管网站」 | 它同时是 issue tracker、PR 评审平台、发布分发渠道和项目主页 |
